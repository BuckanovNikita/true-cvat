# CVAT fork reference

Read on demand. Rules that bind every change are in [AGENTS.md](AGENTS.md); the Russian overview is [README.fork.md](README.fork.md).

## Architecture and data flow

- Repository `BuckanovNikita/true-cvat`, a GitHub fork of `cvat-ai/cvat` on upstream v2.82.0. `main` = the upstream release, nothing else; `develop` = `main` plus a linear, merge-free line of fork commits; `release` = `develop` without `local/`. Stage tags `v<upstream>.<n>` (n from 1 per upstream release) mark merges into `release`; they change no version string, chart version or image tag and get no GitHub Release (Helm and npm accept three-part versions only).
- Fork-owned root paths: `local/`, `tools/`, `verify/`, `helm-chart-nuclio/`, `AGENTS.md`, `DOCS.md`, `README.fork.md`, `build-server.sh`, `build-ui.sh`, `Dockerfile.server`, `Dockerfile.ui.dockerignore`, `ruff.toml`. The checks' Python pin is `tools/gate/pyproject.toml` + `uv.lock` (the root `pyproject.toml` is upstream's).
- Edited upstream backend files: `cvat/apps/engine/rules/{issues,comments}.rego`, `cvat/apps/engine/rules/tests/configs/{issues,comments}.csv` (rows added only), tails of `cvat/settings/base.py`, `cvat/urls.py`, `.gitignore`; `Dockerfile.ui` (bases and npm registry as args). Added: `cvat/apps/team_analytics/`, `backend_entrypoint.d/team_analytics.conf`, the worker template under `helm-chart/templates/cvat_backend/worker_team_analytics/`.

## Domain terms

- **Team Analytics** (not "Analytics"/dashboard); **Grafana** = the stock header link, renamed from "Analytics". **Annotator**: a person whose work counts (reviewers count, technical accounts do not).
- **Session**: activity with gaps under five minutes, at most one day. **Idle pause**: a pause over 100 s before an action; belongs to no operation. **Working time**: the server's figure (as in Grafana), the only total. **Other**: working time outside the four operations, for the shown scope, floored at zero.
- **Operation**: exactly Creation, Alignment, Class change or Deletion; counts what people did (an undone creation counts, a redo does not). **Alignment**: an uninterrupted run of drags/resizes of one object; a group move is one alignment per object, time shared equally. **Time per operation**: from the previous action to the end of the operation.
- **Creation methods**: Drawn, Pasted, Propagated, Model. **Model** boxes (saved by a technical account or the built-in detector) have counts but no time; tags, interactor and OpenCV objects are not creations.
- **Hotkey actions** are named by function; a held key is one action except frame navigation (one per frame moved). **Mouse actions**: clicks on buttons, menus, sidebar controls, not the canvas. **Hotkey share** = hotkey / (hotkey + mouse). Recorded only in 2D jobs; 3D jobs give sessions and working time only.
- **Technical accounts list**: one instance-wide list in Postgres by user id, kept by administrators; applies retroactively; a deleted account stays listed (`deleted: true`).
- **Organization scope** (admin with an org selected) / **Instance scope** (admin, no org: all orgs plus personal workspaces). Tasks without a project form "No project"; a deleted project stays under its id.
- **Periods**: Week, Two weeks, Month (calendar, selectable), Year (12 months), viewer's time zone. **Trends**: last 12 weeks or months. **Comparison**: up to five annotators or projects. **Full view**: a chart's expanded view (not "modal"). **Bounding box** (never "bbox" in UI text).
- **Cutover**: hour of the first shape-tagged operation event on the instance; stored, only moves earlier. **Legacy period**: ends at/before the cutover (or none exists): sessions, working time, projects, all-shape operations, saved boxes only. **Partly legacy period**: counts operations only under All shapes before the cutover.
- **Processed history**: a period is offered only when fully processed; history fills newest first; a warning shows when data is over 30 min old.
- The page is in Russian (ADR 0010); the terms above stay English in code, comments and documents. Russian wording on the page: Annotator = Аннотатор; Technical account = Техническая учётная запись; Team Analytics settings = Настройки Team Analytics; job work = работа в заданиях (job = задание, task = задача); Organization = Организация, instance scope = Все организации и личные пространства; No project = Без проекта; Session = Сессия (the sign-in session is «сеанс»); Working time = Рабочее время; Time per operation = Время на операцию; Bounding boxes = Боксы, All shapes = Все фигуры (object = объект); Operation = Операция; Creation / Alignment / Class change / Deletion / Other = Создание / Подгонка / Смена класса / Удаление / Прочее; Creation method = Способ создания; Drawn / Pasted / Propagated / Model = Нарисовано / Вставлено / Распространено / Модель; Saved boxes = Сохранённые боксы; Hotkey action = Действие горячей клавишей (plural Действия горячими клавишами); Mouse action = Действие мышью; Hotkey share = Доля горячих клавиш; Period = Период (Неделя, Две недели, Месяц, Год); Trends = Динамика; Comparison = Сравнение; Overview = Обзор; Full view = Полный вид; Processed history = Обработанная история; new activity logging (what starts at the cutover) = новый учёт действий. "Team Analytics", "Grafana" and "CVAT" are not translated.
- UI wording of these terms is copied by hand, in Russian, into `cvat-ui/src/components/team-analytics-page/{definitions.tsx,creation-methods.ts,settings-modal.tsx}` and asserted by `verify/team-analytics-page/definitions.test.cjs` and the stack's `fixes_browser.cjs`.

## Decisions

### ADR 0001
Thin separate analytics service with stored totals. Superseded by ADR 0006; its figure rules stay (calculations are SQL over stored hourly totals; session gap and idle pause fixed at computation time, so changing them means recomputing history).
### ADR 0002
New measurements ride inside existing event types: never add an event type or client scope (one unknown scope makes the server reject the whole batch and the client resends forever); extra payload fields or `debug:info` records told apart by name; every logging call guarded, fire-and-forget, logged through the job with project/task/job ids.
### ADR 0003
Kubernetes only, with the in-tree upstream Helm chart; Compose unsupported (it starts no Team Analytics worker), upstream Compose files stay untouched. Test infrastructure runs in its own namespace with ResourceQuota and LimitRange.
### ADR 0004
Server image adding only the patched policies over the stock image. Superseded by ADR 0007.
### ADR 0005
Full-source fork joined to upstream by one merge. Superseded by ADR 0009.
### ADR 0006
Team Analytics inside the backend (`cvat/apps/team_analytics/`), behind CVAT's OPA permissions; the API process does no analytical work (access check, Redis cache, else queue to the `team_analytics` worker and reply 429 with `Retry-After`); one worker Deployment of the fork server image runs reads and the periodic refresh; endpoints excluded from `cvat/schema.yml` and the SDK. Rejected: Grafana queries (per-user flag exposes all orgs), a second API server routed by path, queries in the API process with limits.
### ADR 0007
Images from public bases; the server image is `Dockerfile.server`, a stage-for-stage port of upstream's `Dockerfile` to Debian 12 on `python:3.12-slim-bookworm`; no fork Dockerfile starts `FROM` a `cvat/` image; base defaults are public `tag@digest` references, but a digest is not required (mirrors re-push with other digests, so a plain tag is accepted); `build-server.sh` logs the digest each base resolved to. Deviations: Debian 12 packages (nginx 1.22, older git/poppler/OpenLDAP), `unrar` from non-free enabled only while installing, a Debian Python 3.11 in `/usr/bin` used only by supervisord.
### ADR 0008
The fork is the original for two repositories: a downstream repository vendors the build set and both charts. Renaming a chart value, a vendored file or a build arg is breaking and must be coordinated downstream. Every closed-network input is a Dockerfile ARG with a public default; no corporate hosts or credentials in the repository (it is public).
### ADR 0009
Three branches in a GitHub fork, `develop` rebased onto each upstream release; never use GitHub's "Sync fork". `BuckanovNikita/cvat-fork` is the frozen earlier history; `develop` commits carry `Landed-as:` trailers naming cvat-fork commits.

### ADR 0010
The Team Analytics page is in Russian only, by the owner's decision of 2026-11-21: Russian replaces English in the page's own files (`cvat-ui/src/components/team-analytics-page/`), with no language switch, no translation library and no stored language preference; the rest of CVAT stays English. No dependency is added (`package.json` and `yarn.lock` are in the downstream-vendored set, ADR 0008) and no upstream file is edited. Numbers, durations and dates go through the page's `format.ts` and plural forms through `plural.ts` (`Intl.PluralRules`); neither reads the browser's language. Keys in the page address and in service requests are unchanged. Left in English: the header link "Team Analytics", hotkey names from upstream's keymap and the server's refusal reasons. Rejected: both wordings in a dictionary with the language taken from the browser (every string and test twice); the same with a switch on the page (a control and a stored preference on top); a translation library with antd's `ConfigProvider` at the application root (a new dependency and an edit to upstream's `index.tsx`). An English page later means bringing back a second wording: a new decision.

## Team Analytics (TA-1)

- Layout: `core/` calculation and engine (no Django), `sql/` every statement, `views.py`/`urls.py`/`permissions.py`/`rules/team_analytics.rego` access, `serializers.py`/`technical_accounts.py` settings, `reads.py` read path, `jobs.py` (`read_answer`, `refresh_totals`), `default_settings.py`, `models.py` (`TechnicalAccount`, migration `0001_initial`). No signal handlers. The API side must import nothing that connects to ClickHouse.
- Wiring in `cvat/settings/base.py`: queue `team_analytics` in `RQ_QUEUES` on `REDIS_INMEM_SETTINGS` always (so `syncperiodicjobs` clears a stale schedule); only with `CVAT_ANALYTICS` the app in `INSTALLED_APPS` and job `team_analytics_refresh` (`cvat.apps.team_analytics.jobs.refresh_totals`, every minute) in `PERIODIC_RQ_JOBS`; `cvat/urls.py` adds routes under `api/`. Analytics off: endpoints 404, no worker, no header link.
- Endpoints (no trailing slash): `GET /api/team-analytics/{status,overview,trends,list,details}` (cache or worker); `GET`/`PUT /api/team-analytics/settings`, `GET settings/users?search=` (max 20 users, 150 chars), `GET project-names?ids=` (max 500) from Postgres. Responses 200, 400 `{"error":"bad_request","detail":...}`, 401, 403, 404 unknown org, 429 + `Retry-After`, 503 `{"error":"unavailable"}`; all `Cache-Control: no-store`.
- Access: administrators only (`admin` group), scopes `view` and `update` (PUT settings), no caller cache; org owners/maintainers get 403; the page sends no request for non-admins and shows its not-available state («Страница Team Analytics недоступна»).
- Page language (ADR 0010): every text the page shows is Russian, written in the page's files: visible text, `title`, `aria-label`, placeholders. `format.ts` formats numbers, durations and dates (`1 200`, `3,8 с`, `7 нояб.`; U+00A0, written as `NBSP` or `\u00a0`, groups digits and joins a number to its unit or word); `plural.ts` gives `plural(count, [one, few, many])`, and a phrase that depends on a count or on the shape, the dimension or the unit is a whole phrase per variant, never a noun glued into a frame. The page root and the settings dialog carry `lang='ru'`. The settings dialog has its own close button, because antd 5.17 gives its own the fixed label "Close". A refused settings save shows «Сервер не принял список:» and the server's reason unchanged. `verify/team-analytics-page/russian.test.cjs` fails on a Latin word outside its allowlist in a rendered state; `format.test.cjs` covers the helpers.
- Settings PUT body `{"technical_accounts": [ids]}` replaces the list (positive ints, unique, max 1,000, new ids must exist), takes a table lock, then advances the answer generation; 503 if it cannot.
- Reads: cache key = SHA-256 of endpoint, organization, kept params (`ENDPOINT_PARAMETERS`, `MAX_LENGTH` in `reads.py`) and UTC hour, not the caller; answers stored with the totals generation (`advance_generation`), which is not in the key. A miss enqueues one job per key; 429 when `READ_QUEUE_LIMIT` reads queue or the enqueue lock is held over 1 s; else the cache is polled every 50 ms for `READ_WAIT_S`. cvat-core retries 429 three times (29 s with defaults).
- Refresh: lock Redis key `team_analytics:refresh` (120 s, extended every 40 s, released by token); steps by priority (recent-hours refresh when due, one history day newest first, daily check), yields when a read waits or after `REFRESH_BUDGET_S`; advances the generation once per run only if visible data may have changed (`core/run.py`); visibility via `hour_versions` (`latest_version.sql`); make-ready mark `team_analytics:ready`. A worker killed inside a step holds refreshes up to 120 s. Redis data loss drops the refresh schedule until the entry point's `init` reruns `syncperiodicjobs` (rerun the backend initializer); the ready mark and generation are rebuilt by the next job.
- Settings (env of the same name, Django setting wins, invalid values logged and defaulted), prefix `TEAM_ANALYTICS_`: `DB`=team_analytics, `REFRESH_INTERVAL_S`=600, `REFRESH_WINDOW_HOURS`=48, `LOOKBACK_S`=300, `REFRESH_BUDGET_S`=45, `REFRESH_STATEMENT_S`=300, `READ_WAIT_S`=5, `READ_RETRY_AFTER_S`=3, `READ_QUEUE_LIMIT`=32, `READ_STATEMENT_S`=20, `READ_STATEMENT_MEMORY_BYTES`=536870912, `READ_JOB_TIMEOUT_S`=90 (abandoned after 2x+120 s), `ANSWER_TTL_S`=900, `FAILURE_TTL_S`=5.
- Fixed in `core/config.py`: refresh lease 120 s; cutover search limits 23 s at start, 60 s in the daily check, 512 MiB, sent as ClickHouse `max_execution_time` with `timeout_overflow_mode=throw`.
- Cutover correction: delete the wrong event from `events`, then all rows of the totals `cutover` table, then wait for the daily check. Any account can forge its own figures or move the cutover: accepted because only admins read.
- Counting: a redo is no operation; a group move logs one `drag:object` per object with `group`=`move` (CVAT's grabbed drag `group`=`grabbed` is no operation); a frame-navigation hotkey counts each frame change started within a 100-microtask turn; logging stops after three failures; changed counting rules do not recompute stored hours.
- Upstream internals relied on (diff them on every upgrade): `OpenPolicyAgentPermission`/`PolicyEnforcer`, `load_app_iam_rules`, `RQ_QUEUES`/`PERIODIC_RQ_JOBS`/`REDIS_INMEM_SETTINGS`, `syncperiodicjobs`, `request.iam_context`, `utils.is_admin`, User/Project models, `backend_entrypoint.d/*.conf` and `NUMPROCS`, chart helpers, `caches["default"]`, cvat-core `serverRequest`/axios-retry/`generateError`, `generate_tests.py`, the `events` schema and Vector's field allowlist, canvas `canvas.groupmoved` before `canvas.dragshape`, `createAnnotationsAsync` resolving to created client ids (`[]` on failure), `/api/server/plugins` (`ANALYTICS`) and the `admin` group, `organizations.current`, CVAT's `#root` minimum width and header layout, shortcut action names; for IAM-2, the organizations app taking its default only when Django settings have none. Frame changes go only through `changeFrameAsync`.

### Known limit of unprocessed periods
An answer for a period not fully processed keeps only its envelope with `processed: false`; every figure is null (overview keeps `period`, `filters`, legacy flags; list keeps `period`, `by`, flags; details keeps `by`, `page_size`, `technical_accounts`, flags; trends null the points of unprocessed buckets). Implemented in `core/withheld.py`. Legacy flags of such an answer describe only the processed part and can flip once processing completes.

## Operations

### Upstream upgrade
1. Record the start once (never re-run to resume): `git fetch origin && git update-ref refs/upgrade/base origin/main && git update-ref refs/upgrade/start origin/develop`. The `upstream` remote (`https://github.com/cvat-ai/cvat.git`) has no fetch refspec; fetch tags by name: `git fetch --filter=blob:none --no-tags upstream refs/tags/<tag>:refs/tags/<tag>`.
2. Rebase: check `git merge-base --is-ancestor refs/upgrade/base "${TARGET}^{commit}"` and no merges in `refs/upgrade/base..refs/upgrade/start`; `git switch -c upgrade/cvat-${TARGET} refs/upgrade/start && git rebase --onto "${TARGET}^{commit}" refs/upgrade/base`. Commits landing on `develop` meanwhile are cherry-picked (never merged) after the rebase finishes, with the upgrade branch checked out: `git fetch origin && git cherry-pick refs/upgrade/start..origin/develop && git update-ref refs/upgrade/start origin/develop`. The update-ref runs only when every pick applied; on a conflict resolve, `git cherry-pick --continue`, then run the update-ref alone without fetching again. `refs/upgrade/start` must only ever name a `develop` commit whose whole history the upgrade branch carries, or step 5 replaces `develop` without the missing commits. Expected conflicts: the edited UI files, both policies and their CSVs, `.github/` (keep deleted; remove files the release adds there in a final commit), appended tails (upstream lines, then the fork block), `helm-chart/` and `Dockerfile.ui` args (keep every published name). A `helm-chart/Chart.yaml` conflict keeps the fork's dependency set (no nuclio dependency); when upstream's dependency version line moves, re-copy the tarball into `charts/` and update `Chart.lock`.
3. Check the policies and update the images: `git diff "${TARGET}" HEAD -- cvat/apps/engine/rules` must show only the two marked additions and added CSV rows; compare helper policies; review new scopes. Bump `v2.82.0` defaults together (`git grep -n -F v2.82.0` over fork files): `build-ui.sh`, `build-server.sh`, `tools/gate/ui-lint.sh` (`UPSTREAM_TAG`), `verify/policy_test.sh` (`STOCK_TAG`), `verify/policy_bundle.sh`, `verify/team_analytics_backend.sh`, the stack's `stack.env` and `run.sh`. Port `git diff <old> "${TARGET}" -- Dockerfile` into `Dockerfile.server` (Ubuntu package names -> Debian 12, keep commented deviations, new COPY paths into `COPIED`, new bases when versions move), then set `PORTED_FROM_SHA256` to `sha256sum Dockerfile`. Rebuild both images.
4. Verify the integrated changes: run every command of "Checks" in AGENTS.md, the out-of-band checks, the bundle check against the new image, and a stack `cycle`. Read the release's changes to the upstream internals listed under Team Analytics:

   ```bash
   git diff v2.82.0 "${TARGET}" -- cvat/apps/iam/permissions.py cvat/apps/iam/middleware.py \
       cvat/apps/redis_handler/management/commands/syncperiodicjobs.py cvat/settings/base.py cvat/requirements \
       cvat/apps/iam/models.py cvat/apps/engine/models.py cvat/apps/organizations/{apps.py,default_settings.py,permissions.py,rules/organizations.rego} \
       backend_entrypoint.sh backend_entrypoint.d helm-chart/templates/_helpers.tpl helm-chart/templates/cvat_backend \
       cvat-core/src/server-proxy.ts cvat-core/src/axios-config.ts cvat/apps/iam/rules/tests/generate_tests.py
   ```
5. Hand off (owner's word only): verify `origin/main` == `refs/upgrade/base` and `origin/develop` == `refs/upgrade/start`, review with `git range-diff refs/upgrade/base..refs/upgrade/start "${TARGET}..upgrade/cvat-${TARGET}"`, then `git push --atomic --force-with-lease="develop:$(git rev-parse refs/upgrade/start)" origin "${TARGET}^{commit}:refs/heads/main" "upgrade/cvat-${TARGET}:develop"` (the only forced push allowed) and delete both `refs/upgrade` refs. Afterwards refresh local branches (`git fetch origin main:main`; `git switch -C develop origin/develop` once `git log origin/develop..develop` holds nothing wanted) and rebase open task branches onto the new `develop`. Before an authorized deployment keep the previous UI and server images and the deployment configuration, and plan the database backup and rollback for the target release: moving branches back does not undo DB migrations.

### Cut a release
Owner's word only, from published `develop`. `STAGE` is one more than the highest of `git tag -l 'v2.82.0.*'` (first on a new upstream release: `${TARGET}.1`). Run as one command; the `&&` chain stops at the first failure, so nothing is tagged or pushed:

```bash
STAGE=v2.82.0.N; WHAT="what the stage delivers"
git fetch origin &&
! git rev-parse -q --verify "refs/tags/${STAGE}" >/dev/null &&        # the stage tag is new
! git merge-base --is-ancestor origin/develop origin/release &&      # there is something to cut
[ -z "$(git status --short --untracked-files=no)" ] &&               # the block overwrites the working tree
git switch -C release origin/release &&
git merge --no-ff --no-commit -s ours origin/develop &&              # develop becomes the second parent
git read-tree -u --reset origin/develop &&                           # take develop's tree exactly
git rm -r -q -f --ignore-unmatch local &&                            # -f: the files are staged
git commit -m "release: ${STAGE}, ${WHAT}" &&
[ "$(git branch --show-current)" = release ] &&
[ "$(git rev-parse HEAD^1)" = "$(git rev-parse origin/release)" ] &&
[ "$(git rev-parse HEAD^2)" = "$(git rev-parse origin/develop)" ] &&
[ -z "$(git diff --name-only origin/develop HEAD | grep -v '^local/')" ] &&
[ -z "$(git ls-tree --name-only HEAD -- local)" ] &&
git tag -a "${STAGE}" -m "Stage ${STAGE##*.}: ${WHAT}" &&
git push --atomic origin release "${STAGE}"
```

A stop at the second or third check means there is nothing to cut. If it stops after the merge began: `git merge --abort`, plus `git tag -d "${STAGE}"` if the tag was made but not pushed, then rerun.
