# Настройки сервера, которые видит пользователь

Здесь собраны настройки (settings) сервера, от которых зависит, что пользователь (user) видит в интерфейсе: кто создаёт организации, есть ли в шапке ссылки на аналитику и как быстро отвечает страница Team Analytics ([Team Analytics](../../../GLOSSARY.md#team-analytics)). Страница объясняет, почему интерфейс ведёт себя так, а не иначе, и что может изменить тот, кто разворачивает сервер.

## Кто задаёт настройки

Все настройки на этой странице — переменные окружения (environment variables) процессов сервера. Сервер читает их при запуске: новое значение действует только после перезапуска процессов.

Эта страница говорит о том, что каждая настройка меняет для пользователя, и называет значение по умолчанию только там, где пользователь видит его действие: кто создаёт организации, как часто обновляются показатели, сколько страница ждёт ответа. Все значения по умолчанию, допустимые значения, что сервер делает с неверным значением и где задать переменную при установке, описаны в документации для DevOps (на английском): [Backend configuration](../../configuration.md).

## Создание организаций

`CVAT_ORGANIZATIONS_MIN_ROLE_TO_CREATE` — наименьшая глобальная роль ([global role](../../../GLOSSARY.md#global-role)), с которой учётная запись (account) может создать организацию (organization).

- В форке по умолчанию `admin`: организации создают только администраторы.
- В CVAT по умолчанию `user`: организацию может создать любая учётная запись с глобальной ролью `user` или `admin`.

| Значение | Кто может создать организацию |
| --- | --- |
| `admin` | Только администраторы (группа `admin`). |
| `user` | Учётные записи с глобальной ролью `user` и администраторы. |
| `worker` | Все учётные записи с глобальной ролью `worker`, `user` или `admin`. |
| любое другое | Только администраторы: администратору создание разрешено всегда. |

Настройка проверяется только при создании организации. Уже существующие организации, их участники и роли от неё не зависят.

Что видит пользователь без права на создание, описано в [organization-creation.md](organization-creation.md). Как задать настройку при установке — в разделе [Organization creation](../../configuration.md#organization-creation-cvat_organizations_min_role_to_create).

## Включение аналитики

`CVAT_ANALYTICS` включает аналитику на сервере. По умолчанию она выключена. Значения `true`, `t`, `yes`, `y`, `on`, `1` (в любом регистре) включают её, `false`, `f`, `no`, `n`, `off`, `0` — выключают; с другим значением сервер не запускается.

Когда аналитика выключена, пользователь теряет:

| Что пропадает | Почему |
| --- | --- |
| Ссылка «Grafana» в шапке (header) | Шапка показывает её только когда сервер сообщает, что аналитика включена, и у пользователя есть доступ к аналитике. |
| Ссылка «Team Analytics» в шапке | Шапка показывает её только администратору и только при включённой аналитике. |
| Проверка доступа к Grafana по адресу `/analytics` на сервере CVAT | Приложение, которое отвечает по этому адресу, подключается только при включённой аналитике. |
| Страница Team Analytics и её API `/api/team-analytics/*` | Приложение Team Analytics и его адреса подключаются только при включённой аналитике. На такие запросы (requests) сервер отвечает `404`, и страница `/team-analytics` показывает панель «Страница Team Analytics недоступна», как пользователю без прав. |
| Обновление сохранённых итогов Team Analytics | Периодическая задача обновления регистрируется только при включённой аналитике. |

Подробнее о ссылках в шапке: [grafana-link.md](grafana-link.md). О состояниях страницы: [team-analytics.md](team-analytics.md).

## Настройки Team Analytics

Эти настройки действуют только при включённой аналитике. Время в названиях: `_S` — секунды, `_HOURS` — часы. Значение по умолчанию и наименьшее допустимое значение каждой настройки — в таблице [Team Analytics settings](../../configuration.md#team-analytics-settings).

| Настройка | Что меняется для пользователя |
| --- | --- |
| `TEAM_ANALYTICS_DB` | Имя базы ClickHouse, где лежат сохранённые итоги. Пользователь его не видит. Если указать новую, пустую базу, сервер создаёт её и заполняет заново; что страница показывает, пока обработанная история ([Processed history](../../../GLOSSARY.md#processed-history)) не готова, описано в [team-analytics-figures.md](team-analytics-figures.md). |
| `TEAM_ANALYTICS_REFRESH_INTERVAL_S` | Как часто пересчитываются последние часы. Цифры на странице могут отставать от работы в заданиях примерно на это время (по умолчанию около 10 минут). |
| `TEAM_ANALYTICS_REFRESH_WINDOW_HOURS` | Сколько последних часов пересчитывается при каждом обновлении. События, которые попали на сервер с опозданием, но не старше этого окна, войдут в цифры. |
| `TEAM_ANALYTICS_LOOKBACK_S` | Насколько раньше окна пересчёта читаются события. Пользователь этого не замечает: так действие, начатое незадолго до окна, считается целиком. |
| `TEAM_ANALYTICS_REFRESH_BUDGET_S` | Обновление запускается каждую минуту и после стольких секунд не начинает новый шаг (обновление последних часов, день истории). Чем меньше значение, тем медленнее обрабатывается история. |
| `TEAM_ANALYTICS_REFRESH_STATEMENT_S` | Предел одного запроса к ClickHouse при обновлении. Если он превышен, обновление не удаётся и повторяется при следующем запуске; цифры дольше остаются старыми. |
| `TEAM_ANALYTICS_READ_WAIT_S` | Сколько сервер ждёт ответа (response), которого ещё нет в кэше, прежде чем ответить `429`. `0` — отвечать сразу. |
| `TEAM_ANALYTICS_READ_RETRY_AFTER_S` | Пауза в заголовке `Retry-After` ответа `429`: через столько секунд страница спрашивает снова. |
| `TEAM_ANALYTICS_READ_QUEUE_LIMIT` | Сколько чтений может ждать в очереди. Сверх этого запрос сразу получает `429`, и при постоянной перегрузке страница показывает ошибку быстрее, примерно через 9 секунд. |
| `TEAM_ANALYTICS_READ_STATEMENT_S` | Предел одного запроса к ClickHouse при чтении цифр. Если он превышен, сервер отвечает `503`, и страница показывает ошибку. |
| `TEAM_ANALYTICS_READ_STATEMENT_MEMORY_BYTES` | Предел памяти одного запроса к ClickHouse при чтении. Если он превышен, сервер отвечает `503`, и страница показывает ошибку. |
| `TEAM_ANALYTICS_READ_JOB_TIMEOUT_S` | Предел одного чтения целиком и срок, который чтение может ждать в очереди. Чтение, которое не уложилось, прерывается или не начинается: страница получает `503` либо так и не получает ответа и после повторов показывает панель ошибки. |
| `TEAM_ANALYTICS_ANSWER_TTL_S` | Сколько готовый ответ хранится в кэше, если его больше никто не запрашивает. Цифры от этого не устаревают: ответ используется, только пока итоги не обновились. |
| `TEAM_ANALYTICS_FAILURE_TTL_S` | Сколько секунд сервер помнит неудачное чтение. Если повторить запрос в это время, страница сразу снова покажет ошибку. |

### Почему страница ждёт 29 секунд

Пока ответа нет в кэше, страница ждёт так (числа — для значений по умолчанию):

1. Сервер ставит чтение в очередь и ждёт ответа до `TEAM_ANALYTICS_READ_WAIT_S` (5 секунд). Ответ готов — страница получает цифры.
2. Ответа нет — сервер отвечает `429` с заголовком `Retry-After`, равным `TEAM_ANALYTICS_READ_RETRY_AFTER_S` (3 секунды).
3. Интерфейс CVAT повторяет запрос после `429` через `Retry-After` секунд, не больше трёх раз. Каждый повтор снова ждёт на сервере до 5 секунд.
4. Если и после третьего повтора ответа нет, страница показывает панель ошибки.

Итого: четыре ожидания по 5 секунд и три паузы по 3 секунды, 4 × 5 + 3 × 3 = 29 секунд. С другими значениями время до панели ошибки — 4 × `TEAM_ANALYTICS_READ_WAIT_S` + 3 × `TEAM_ANALYTICS_READ_RETRY_AFTER_S`. Как только ответ появился в кэше, ближайший запрос получает его.

### Неверное значение

Неверное значение числовой настройки не мешает CVAT запуститься: сервер записывает ошибку в журнал и берёт значение по умолчанию, так что для пользователя страница работает как без настройки. Какие значения считаются неверными и как выглядит запись в журнале, описано в разделе [Invalid values](../../configuration.md#invalid-values).

### `TEAM_ANALYTICS_TECHNICAL_ACCOUNTS` не действует

Эта переменная окружения не задаёт список «Технические учётные записи» ([Technical accounts list](../../../GLOSSARY.md#technical-accounts-list)): список хранится в базе данных сервера, и его меняют администраторы в диалоге «Настройки Team Analytics» ([Team Analytics settings](../../../GLOSSARY.md#team-analytics-settings)), см. [team-analytics-settings.md](team-analytics-settings.md). Если переменная задана и не пуста, сервер при запуске пишет в журнал предупреждение, что она игнорируется; на цифры и на список она не влияет. Как перенести список из переменной, описано в документации для DevOps (на английском): [Migrating from `TEAM_ANALYTICS_TECHNICAL_ACCOUNTS`](../../team-analytics.md#migrating-from-team_analytics_technical_accounts).
