# Team Analytics internals (TA-1)

How the Team Analytics app, page and worker are built. Operating it is on [Operating Team Analytics](../team-analytics.md).

## Internals

- Layout: `core/` calculation and engine (no Django), `sql/` every statement, `views.py`/`urls.py`/`permissions.py`/`rules/team_analytics.rego` access, `serializers.py`/`technical_accounts.py` settings, `reads.py` read path, `jobs.py` (`read_answer`, `refresh_totals`), `default_settings.py`, `models.py` (`TechnicalAccount`, migration `0001_initial`). No signal handlers. The API side must import nothing that connects to ClickHouse.
- Wiring in `cvat/settings/base.py`: queue `team_analytics` in `RQ_QUEUES` on `REDIS_INMEM_SETTINGS` always (so `syncperiodicjobs` clears a stale schedule); only with `CVAT_ANALYTICS` the app in `INSTALLED_APPS` and job `team_analytics_refresh` (`cvat.apps.team_analytics.jobs.refresh_totals`, every minute) in `PERIODIC_RQ_JOBS`; `cvat/urls.py` adds routes under `api/`. Analytics off: endpoints 404, no worker, no header link.
- Endpoints (no trailing slash): `GET /api/team-analytics/{status,overview,trends,list,details}` (cache or worker); `GET`/`PUT /api/team-analytics/settings`, `GET settings/users?search=` (max 20 users, 150 chars), `GET project-names?ids=` (max 500) from Postgres. Responses 200, 400 `{"error":"bad_request","detail":...}`, 401, 403, 404 unknown org, 429 + `Retry-After`, 503 `{"error":"unavailable"}`; all `Cache-Control: no-store`.
- Access: administrators only (`admin` group), scopes `view` and `update` (PUT settings), no caller cache; org owners/maintainers get 403; the page sends no request for non-admins and shows its not-available state («Страница Team Analytics недоступна»).
- Page language (ADR 0010): every text the page shows is Russian, written in the page's files: visible text, `title`, `aria-label`, placeholders. `format.ts` formats numbers, durations and dates (`1 200`, `3,8 с`, `7 нояб.`; U+00A0, written as `NBSP` or `\u00a0`, groups digits and joins a number to its unit or word); `plural.ts` gives `plural(count, [one, few, many])`, and a phrase that depends on a count or on the shape, the dimension or the unit is a whole phrase per variant, never a noun glued into a frame. The page root and the settings dialog carry `lang='ru'`. The settings dialog has its own close button, because antd 5.17 gives its own the fixed label "Close". A refused settings save shows «Сервер не принял список:» and the server's reason unchanged. `verify/team-analytics-page/russian.test.cjs` fails on a Latin word outside its allowlist in a rendered state; `format.test.cjs` covers the helpers.
- Settings PUT body `{"technical_accounts": [ids]}` replaces the list (positive ints, unique, max 1,000, new ids must exist), takes a table lock, then advances the answer generation; 503 if it cannot.
- Reads: cache key = SHA-256 of endpoint, organization, kept params (`ENDPOINT_PARAMETERS`, `MAX_LENGTH` in `reads.py`) and UTC hour, not the caller; answers stored with the totals generation (`advance_generation`), which is not in the key. A miss enqueues one job per key; 429 when `READ_QUEUE_LIMIT` reads queue or the enqueue lock is held over 1 s; else the cache is polled every 50 ms for `READ_WAIT_S`. cvat-core retries 429 three times (29 s with defaults).
- Refresh: lock Redis key `team_analytics:refresh` (120 s, extended every 40 s, released by token); steps by priority (recent-hours refresh when due, one history day newest first, daily check), yields when a read waits or after `REFRESH_BUDGET_S`; advances the generation once per run only if visible data may have changed (`core/run.py`); visibility via `hour_versions` (`latest_version.sql`); make-ready mark `team_analytics:ready`. A worker killed inside a step holds refreshes up to 120 s. Redis data loss drops the refresh schedule until the entry point's `init` reruns `syncperiodicjobs` (rerun the backend initializer); the ready mark and generation are rebuilt by the next job.
- Settings (prefix `TEAM_ANALYTICS_`; env of the same name, Django setting wins, invalid values logged and defaulted): names, defaults and minimums are on [Backend configuration](../configuration.md). A read is abandoned after 2x `READ_JOB_TIMEOUT_S` + 120 s.
- Fixed in `core/config.py`: refresh lease 120 s; cutover search limits 23 s at start, 60 s in the daily check, 512 MiB, sent as ClickHouse `max_execution_time` with `timeout_overflow_mode=throw`.
- Cutover correction: delete the wrong event from `events`, then all rows of the totals `cutover` table, then wait for the daily check. Any account can forge its own figures or move the cutover: accepted because only admins read.
- Counting: a redo is no operation; a group move logs one `drag:object` per object with `group`=`move` (CVAT's grabbed drag `group`=`grabbed` is no operation); a frame-navigation hotkey counts each frame change started within a 100-microtask turn; logging stops after three failures; changed counting rules do not recompute stored hours.
- Upstream internals relied on (diff them on every upgrade): `OpenPolicyAgentPermission`/`PolicyEnforcer`, `load_app_iam_rules`, `RQ_QUEUES`/`PERIODIC_RQ_JOBS`/`REDIS_INMEM_SETTINGS`, `syncperiodicjobs`, `request.iam_context`, `utils.is_admin`, User/Project models, `backend_entrypoint.d/*.conf` and `NUMPROCS`, chart helpers, `caches["default"]`, cvat-core `serverRequest`/axios-retry/`generateError`, `generate_tests.py`, the `events` schema and Vector's field allowlist, canvas `canvas.groupmoved` before `canvas.dragshape`, `createAnnotationsAsync` resolving to created client ids (`[]` on failure), `/api/server/plugins` (`ANALYTICS`) and the `admin` group, `organizations.current`, CVAT's `#root` minimum width and header layout, shortcut action names; for IAM-2, the organizations app taking its default only when Django settings have none. Frame changes go only through `changeFrameAsync`.

## Page wording

- The page is in Russian (ADR 0010); the glossary terms stay English in code, comments and documents. The Russian wording of each term on the page is its `_Russian_` line in [GLOSSARY.md](../../GLOSSARY.md). "Team Analytics", "Grafana" and "CVAT" are not translated. Words of the page that are not glossary terms: job work = работа в заданиях (job = задание, task = задача); object = объект.
- UI wording of these terms is copied by hand, in Russian, into `cvat-ui/src/components/team-analytics-page/{definitions.tsx,creation-methods.ts,settings-modal.tsx}` and asserted by `verify/team-analytics-page/definitions.test.cjs` and the stack's `fixes_browser.cjs`.

## Known limit of unprocessed periods
An answer for a period not fully processed keeps only its envelope with `processed: false`; every figure is null (overview keeps `period`, `filters`, legacy flags; list keeps `period`, `by`, flags; details keeps `by`, `page_size`, `technical_accounts`, flags; trends null the points of unprocessed buckets). Implemented in `core/withheld.py`. Legacy flags of such an answer describe only the processed part and can flip once processing completes.
