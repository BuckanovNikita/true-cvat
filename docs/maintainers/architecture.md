# Architecture and contracts

What the fork consists of and which contracts other repositories rely on.

## Architecture and data flow

- Repository `BuckanovNikita/true-cvat`, a GitHub fork of `cvat-ai/cvat` on upstream v2.82.0. `main` = the upstream release, nothing else; `develop` = `main` plus a linear, merge-free line of fork commits; `release` = `develop` without `local/`. Stage tags `v<upstream>.<n>` (n from 1 per upstream release) mark merges into `release`; they change no version string, chart version or image tag and get no GitHub Release (Helm and npm accept three-part versions only).
- Fork-owned root paths: `local/`, `tools/`, `verify/`, `helm-chart-nuclio/`, `AGENTS.md`, `GLOSSARY.md`, `docs/`, `README.fork.md`, `build-server.sh`, `build-ui.sh`, `Dockerfile.server`, `Dockerfile.ui.dockerignore`, `ruff.toml`. The checks' Python pin is `tools/gate/pyproject.toml` + `uv.lock` (the root `pyproject.toml` is upstream's).
- Edited upstream backend files: `cvat/apps/engine/rules/{issues,comments}.rego`, `cvat/apps/engine/rules/tests/configs/{issues,comments}.csv` (rows added only), tails of `cvat/settings/base.py`, `cvat/urls.py`, `.gitignore`; `Dockerfile.ui` (bases and npm registry as args). Added: `cvat/apps/team_analytics/`, `backend_entrypoint.d/team_analytics.conf`, the worker template under `helm-chart/templates/cvat_backend/worker_team_analytics/`.
- Edited upstream UI files under `cvat-ui/src/`: `actions/{annotation,tasks}-actions.ts`, `components/annotation-page/annotation-page.tsx`, `.../attribute-annotation-sidebar.tsx`, `.../canvas2d/{canvas-wrapper,selection-context-menu}.tsx`, `.../controls-side-bar/tools-control.tsx`, `.../objects-side-bar/labels-list.tsx`, `components/cvat-app.tsx`, `components/header/header.tsx`, `components/tasks-page/{styles.scss,task-item.tsx}`, `containers/.../object-item.tsx`, `containers/tasks-page/task-item.tsx`, `reducers/{index,tasks-reducer}.ts`, `utils/mousetrap-react.tsx`. Added: `components/tasks-page/task-jobs-progress.tsx`, `utils/task-jobs-summary.ts`, `components/team-analytics-page/`, `utils/team-analytics-logging/`, `components/shortcut-hints/`, `utils/shortcut-hints/`.
- Helm delta: edited `Chart.yaml`, `values.yaml`, `templates/_helpers.tpl`, `cvat_backend/{initializer/job.yml,server/deployment.yml,service.yml}`, `cvat_kvrocks/statefulset.yml`, `cvat_opa/service.yml`; added `analytics/clickhouse/secret.yml`, `image-tags-guard.yml`, `ingress-redirect.yaml`, `ingress-tls-secret.yaml`; `Chart.lock` and dependency tarballs in `charts/` committed (`helm template` needs no network); upstream's `analytics/` symlink replaced by real copies. - Team Analytics flow: the UI logs extra payload fields and `debug:info` records on stock events -> Vector -> ClickHouse `events` -> worker refresh writes hourly per-task totals to ClickHouse database `TEAM_ANALYTICS_DB` -> API reads answers from the Redis cache, misses are computed by the worker.

## Interfaces and contracts

A build input, a chart value and a backend setting each have one home: the page under [docs/](../README.md) that documents it for installers. Changing one changes its page in the same change.

- Server build: inputs, refusals, the checks before tagging and `SAVE=1` are on [build-server.sh](../commands/build-server.md). Maintainer side: the context is the tracked files of the `COPIED` paths, and the script refuses an unported upstream `Dockerfile` (`PORTED_FROM_SHA256`, [upstream upgrade](upstream-upgrade.md) step 3).
- UI build: inputs and behaviour are on [build-ui.sh](../commands/build-ui.md). It builds upstream's `Dockerfile.ui` with `Dockerfile.ui.dockerignore`. Neither build script pushes.
- Downstream-vendored set: `Dockerfile.server`, `Dockerfile.ui`, `Dockerfile.ui.dockerignore`, `build-server.sh`, `build-ui.sh`, `.dockerignore`, `.yarnrc.yml`, `package.json`, `yarn.lock`, `manage.py`, `rqscheduler.py`, `wait_for_deps.sh`, `backend_entrypoint.sh`, `backend_entrypoint.d/`, `supervisord/`, `components/`, `cvat/`, `cvat-core/`, `cvat-data/`, `cvat-canvas/`, `cvat-canvas3d/`, `cvat-ui/`, `helm-chart/`, `helm-chart-nuclio/`, `docs/`, `GLOSSARY.md`.
- Charts: values, the Team Analytics worker and what the two charts must agree on are on [CVAT chart](../charts/cvat.md) and [nuclio chart](../charts/nuclio.md). `helm-chart-nuclio/` is upstream nuclio's templates copied by hand: a nuclio bump is a manual re-copy with a review of its values, not `helm dependency update`.
- Policy bundle: usage, comparisons and refusals are on [verify/policy_bundle.sh](../commands/policy-bundle.md).
- Client events: three `debug:info` records `team_analytics:class_change`, `team_analytics:model_creation`, `team_analytics:input_summary`, plus payload fields on draw/paste/propagate/drag/resize/delete; names are fixed in `cvat-ui/src/utils/team-analytics-logging/contract.ts` and `cvat/apps/team_analytics/sql/` and change together.
